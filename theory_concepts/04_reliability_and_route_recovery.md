# Concept 04: Reliability, ACKs & Dynamic Route Recovery in C

## 1. End-to-End Acknowledgements (ACK)
In multi-hop ad-hoc mesh networks, packet drops frequently occur due to signal loss, movement, or buffer overflow.
- **DATA Packet:** Sent from source to destination (`PACKET_TYPE_DATA`).
- **ACK Packet:** Generated by destination upon receiving DATA packet (`PACKET_TYPE_ACK`), routed back to the source.
- **ACK Message ID Offset:** To prevent deduplication cache drops, ACK packets use an offset ID (`ack_id = data_id + 10000`).

## 2. Dynamic Route Recovery (Alternate Path Fallback)
When an active link severs (`graph_remove_edge(g, u, v)`):
- Static routes fail completely.
- HopNet uses **On-Demand BFS Graph Traversal**: when the primary next-hop fails, BFS recalculates the shortest path using surviving active matrix edges in $O(V + E)$ time, routing packets through secondary branches seamlessly.

## 3. Likely Viva Questions
1. **Q: What is the difference between hop-by-hop ACK and end-to-end ACK?**
   - **A:** Hop-by-hop ACK confirms delivery between two adjacent nodes (e.g. Node 1 $\rightarrow$ Node 2), while end-to-end ACK confirms that the final target (Node 4) received the payload and sends confirmation back to Node 1.
2. **Q: How does HopNet prevent infinite retransmission loops?**
   - **A:** Implements a capped retry counter (`MAX_RETRANSMIT_ATTEMPTS = 3`). If 3 attempts expire without an ACK, transmission is marked failed to conserve channel bandwidth.
